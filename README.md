# WorkHub

Личное адаптивное рабочее пространство: задачи и календарь, клиенты и проекты, потенциальные заказы, финансы, контент-план, библиотека материалов и сметы.

## Что используется

- React + TypeScript + Vite для интерфейса.
- GitHub Pages для бесплатной публикации статического приложения.
- Supabase Free для входа, межустройственной синхронизации и приватных файлов.

Оплата и ИИ-сервисы не подключаются. Для синхронизации нужен один бесплатный проект Supabase. Владелец входит по адресу почты и паролю; RLS-политики ограничивают записи и файлы его учетной записью.

## Локальный режим

Без настройки Supabase WorkHub остается доступен: можно создавать и редактировать записи, они сохраняются в локальном хранилище текущего браузера. На экране постоянно показано, что данные не синхронизируются. Очистка данных сайта браузером удалит эти записи.

## Настройка облачной базы

1. Создайте отдельный проект Supabase на бесплатном тарифе и сохраните Project URL и publishable key.
2. В SQL Editor выполните `supabase/setup.sql`.
3. В Authentication добавьте одного пользователя-владельца с почтой и паролем. Публичную регистрацию оставьте выключенной.
4. Сохраните Project URL и publishable key как секреты репозитория GitHub Actions с именами `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Никогда не добавляйте `service_role` key в приложение или репозиторий.

## Публикация на GitHub Pages

Workflow `.github/workflows/deploy.yml` собирает приложение при каждом push в `main` и публикует каталог `dist`. В настройках репозитория выберите **Settings → Pages → GitHub Actions**. Пока Supabase не подключен, приложение открывается в локальном режиме: записи сохраняются в браузере на этом устройстве. Между устройствами они не синхронизируются. После настройки секретов появятся вход владельца и облачная синхронизация.

Для локального запуска создайте `.env.local` на основе `.env.example`, заполните Supabase URL и publishable key, затем выполните:

```sh
npm ci
npm run dev
```

Сборка для проверки:

```sh
npm run build
```

## Безопасность и хранение

Данные принадлежат только вошедшему пользователю через PostgreSQL Row Level Security. Файлы хранятся в закрытом bucket; ссылка на файл действует пять минут. Публичный репозиторий содержит только исходный код и publishable key через секрет сборки. Пароли и серверные ключи в репозитории не хранятся.
